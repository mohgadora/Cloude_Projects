# سوقنا (Souqna) — خطة بناء المنصة الموحّدة
**مرحلة 1: الموقع الإلكتروني فقط — التطبيقات (Buyer/Supplier/Driver) لاحقاً**

> هذه الوثيقة تدمج بين دراسة "ميزات أمازون الشاملة" (نموذج B2C عام متعدد المراحل) ووثيقة
> "Wholesale E-Commerce Platform PRD" (منصة B2B+B2C جملة/تجزئة مع مقارنة أسعار السوق كميزة تنافسية)
> في خطة تنفيذ واحدة، تبدأ بموقع ويب واحد يخدم الحسابين معاً، على أن تُبنى التطبيقات (Flutter)
> لاحقاً فوق نفس الـ API دون إعادة عمل.

---

## 1. الفكرة الموحّدة

منصة تجارة إلكترونية واحدة بحسابين:

- **حساب مستهلك (B2C):** تسجيل بجوال/بريد، يرى الأسعار بالتجزئة، تجربة شراء شبيهة بأمازون
  (كتالوج، بحث، سلة، دفع، تتبع، تقييمات).
- **حساب تاجر/منشأة (B2B):** تسجيل بسجل تجاري، يرى أسعار الجملة والتسعير المتدرج حسب الكمية،
  سلة تُقسَّم تلقائياً حسب المورد، وطلبات عروض أسعار (RFQ) لاحقاً.

**الميزة التنافسية المحورية (من وثيقة B2B):** مؤشر يقارن سعر كل منتج بسعر السوق الفعلي،
فيظهر للمشتري (تاجر أو مستهلك) شارة "توفير" واضحة. هذه الميزة تُبنى مبكراً (نسخة أولى في
المرحلة 1، نسخة كاملة بالذكاء الدلالي في المرحلة 2) لأنها الفارق التسويقي الأساسي للمنصة، وليست
ميزة "متأخرة" كما في دراسة أمازون العامة.

التوصيل: تبدأ المرحلة 1 بالتكامل مع شركات شحن خارجية (كما في دراسة أمازون)، ثم تنتقل لاحقاً إلى
نظام توصيل خاص بالمنصة (تطبيق سائق) في مرحلة التطبيقات — بدلاً من بنائه من اليوم الأول.

## 2. المراحل الكبرى (Roadmap)

| # | المرحلة | المحتوى | يعتمد على |
|---|---------|---------|-----------|
| **1** | **موقع MVP** | حسابان (مستهلك/تاجر)، كتالوج، بحث، سلة متعددة الموردين، دفع، طلبات، شحن عبر شركة واحدة، شارة توفير أساسية (يدوية/مجدولة) | دراسة أمازون (البنية) + PRD (نوعا الحساب + الشارة) |
| **2** | **الجملة والسوق الكامل (Marketplace)** | لوحة مورد كاملة، تسعير متدرج، عمولات وتسويات، تقييمات، عروض/كوبونات، محرك مقارنة الأسعار الكامل (مطابقة دلالية + اتجاهات + تنبيهات) | PRD (الوحدات 10، 11) + دراسة أمازون |
| **3** | **التطبيقات (Flutter)** | تطبيق المشتري، بوابة المورد كتطبيق، **تطبيق السائق** ونظام التوصيل الداخلي، تتبع حي على الخريطة | PRD (Buyer/Supplier/Driver Apps) |
| **4** | **التوسع والذكاء** | تعدد الدول/العملات/اللغات فعلياً، RFQ بالجملة، محفظة داخلية، اشتراك مميز (اتجاهات الأسعار + تنبيهات + أولوية توصيل)، توصيات ذكية (Qdrant)، شات بوت خدمة عملاء، إعلانات ممولة، تحسين مسارات التوصيل | PRD (Expansion/Internationalization) + دراسة أمازون (وحدة 12، 13) |

**القاعدة الذهبية:** كل شيء يُبنى فوق Backend API واحد (FastAPI) يخدم الموقع الآن، والتطبيقات لاحقاً — لا إعادة بناء منطق العمل عند الانتقال للتطبيقات.

## 3. خريطة الوحدات الوظيفية الموحّدة

### 3.1 الحسابات والمستخدمين
- تسجيل مزدوج: مستهلك (جوال/OTP) وتاجر (سجل تجاري + رقم ضريبي + حساب بنكي) بسير موافقة موثّق
- تسجيل دخول (بريد/جوال OTP/Google/Apple)، تحقق بخطوتين
- دفاتر عناوين، طرق دفع محفوظة، سجل طلبات، إدارة أجهزة/جلسات

### 3.2 الكتالوج والتسعير
- شجرة تصنيفات، متغيرات (لون/مقاس/سعة)، صور/فيديو، مواصفات ديناميكية، SKU موحّد
- **تسعير مزدوج لكل منتج:** سعر تجزئة ثابت + جدول تسعير جملة متدرج حسب الكمية (يظهر على بطاقة المنتج)
- حد أدنى للطلب (MOQ) للتجار، عروض مجدولة (تاريخ بداية/نهاية)
- إدارة مخزون متعدد المستودعات/الموردين

### 3.3 البحث والاكتشاف
- بحث عربي فوري مع تصحيح إملائي وإكمال تلقائي (Meilisearch للـ MVP، مع مسار ترقية لـ Elasticsearch عند الحاجة لمقياس أكبر)
- فلاتر: الفئة، المورد، السعر، التقييم، العلامة التجارية
- صفحات الأكثر مبيعاً والعروض

### 3.4 السلة والدفع
- **سلة متعددة الموردين:** طلب واحد يُقسَّم تلقائياً لكل مورد، كل جزء يُتابع بشكل مستقل
- شحن/ضريبة محسوبة قبل الدفع، قوائم أمنيات
- بوابات دفع: مدى، Visa/MC، Apple Pay، الدفع عند الاستلام، تقسيط (تابي/تمارا)، محفظة داخلية (مرحلة لاحقة)
- **فوترة إلكترونية متوافقة مع ZATCA من اليوم الأول** (QR، XML، UUID) — لا تُؤجَّل

### 3.5 الطلبات والشحن
- دورة حياة الطلب مع تتبع لكل شحنة فرعية عند تعدد الموردين
- تكامل شركة شحن واحدة في MVP (SMSA أو أرامكس)، تتبع مباشر
- إعادة الطلب بضغطة واحدة، قوالب للطلبات المتكررة (يخدم شراء التاجر الأسبوعي)

### 3.6 مقارنة الأسعار (الميزة التنافسية)
- **نسخة MVP:** إدخال يدوي/مجدول لأسعار السوق المرجعية + شارة "أوفر من السوق" على بطاقة المنتج (لا تظهر إلا عندما السعر فعلاً أقل)
- **نسخة المرحلة 2:** جمع تلقائي من مصادر معلنة، مطابقة منتجات بالباركود والتشابه الدلالي (Qdrant + embeddings — نفس البنية التحتية المتاحة لديك على Contabo)، متوسط مرجّح لكل دولة، مستوى ثقة وعدد مصادر، مخطط اتجاه السعر (30/90 يوم) حصري للمشتركين المميزين، وتنبيهات انخفاض السعر

### 3.7 البائعون/الموردون (Marketplace)
- لوحة مورد: منتجات، طلبات، تقارير، تسويات مالية (Payouts) بكشف حساب دوري
- عمولة قابلة للتخصيص حسب الفئة/المورد (نموذج إيراد أساسي)
- تقييم مستقل للمورد، طلبات عروض أسعار بالجملة (RFQ) في مرحلة التوسع

### 3.8 التقييمات وخدمة العملاء
- تقييم نجوم + مراجعة + صور، شراء موثّق، أسئلة وأجوبة
- مركز مساعدة، تذاكر، شات بوت لاحقاً (Ollama/Qwen)

### 3.9 لوحة الإدارة (Admin Console)
- غرفة عمليات حية: طلبات اليوم، المتأخرة، أداء الموردين، التحصيلات النقدية
- موافقات التسجيل (تاجر/مورد)، إعدادات العمولة ورسوم التوصيل لكل منطقة
- تقارير مالية قابلة للتصدير، **إدارة دول** (عملة، ضريبة، طرق دفع، لغة) — جاهزة بنيوياً من اليوم الأول حتى لو تعمل المنصة في دولة واحدة بداية

### 3.10 البنية غير الوظيفية
- عربي RTL أولاً + إنجليزي، الترجمة على مستوى قاعدة البيانات لا الواجهة فقط
- عملات متعددة (بنية جاهزة من البداية)، SEO (Next.js SSR)، أداء وCDN

## 5. البنية التقنية الموحّدة

| الطبقة | الاختيار | ملاحظة الدمج |
|--------|----------|---------------|
| Backend API | **FastAPI (Python)** | متفق عليه في كلا المصدرين |
| قاعدة البيانات | **PostgreSQL** + **Redis** (كاش/جلسات/سلة) | متفق عليه |
| البحث | **Meilisearch** في MVP، ترقية لـ **Elasticsearch** عند الحاجة (وثيقة B2B تفترضه من البداية، لكن Meilisearch أبسط ويكفي لحجم البداية) | قرار دمج |
| الواجهة (الموقع) | **Next.js (React)**، SSR لـ SEO | من دراسة أمازون (التطبيقات لاحقاً بـ Flutter كما في PRD) |
| مقارنة الأسعار/التوصيات | **Qdrant + نماذج Embeddings** (متاحة أصلاً على سيرفرك) | مطلوبة لمطابقة المنتجات دلالياً في محرك المقارنة |
| التخزين | S3-متوافق (MinIO/Cloudflare R2) + CDN | |
| الخرائط والتتبع | Google Maps Platform | يُفعَّل مع تطبيق السائق في المرحلة 3 |
| الدفع | Moyasar/Tap (مدى، Apple Pay، بطاقات) + تابي/تمارا | |
| الجوال (لاحقاً) | **Flutter** — كود واحد لتطبيقات المشتري/المورد/السائق | |
| البنية التحتية | Docker Compose على Contabo، نسخ احتياطي يومي ومراقبة | |

## 7. خطة سبرنتات المرحلة 1 (موقع MVP، سبرنتات أسبوعين)

1. إعداد المشروع: Docker، PostgreSQL، هيكل FastAPI، المصادقة (JWT + OTP) لحسابي مستهلك/تاجر
2. الفئات والمنتجات + المتغيرات + التسعير المتدرج + لوحة إدارة أساسية
3. رفع الصور، Meilisearch، صفحات الكتالوج في Next.js (RTL أولاً)
4. السلة متعددة الموردين (Redis) + قوائم الأمنيات + صفحة المنتج كاملة
5. Checkout + بوابة الدفع + الدفع عند الاستلام + فوترة متوافقة مع ZATCA
6. دورة حياة الطلب (بتقسيم الشحنات) + الفواتير PDF + إشعارات
7. تكامل شركة شحن واحدة + التتبع + **شارة مقارنة الأسعار (نسخة MVP اليدوية/المجدولة)**
8. SEO، الأداء، الاختبارات، الإطلاق التجريبي

---

## 8. اعتبارات لا تُؤجَّل

- **ZATCA:** الفوترة الإلكترونية إلزامية بالسعودية — تُصمَّم من اليوم الأول
- **RTL أولاً:** الواجهة عربية ثم إنجليزية، وليس العكس
- **الدفع عند الاستلام** ما زال أساسياً في السوق
- **بنية تعدد الدول/العملات/اللغات** تُبنى بشكل جاهز في المخطط منذ البداية (حتى لو التشغيل الفعلي في دولة واحدة الآن) — تفادياً لإعادة هيكلة لاحقة عند التوسع الدولي (PRD)
- **شارة مقارنة الأسعار** لا تُؤجَّل لمرحلة متأخرة كما في دراسة أمازون العامة؛ نسخة أولى منها جزء من MVP لأنها الميزة التسويقية المحورية للمنتج
